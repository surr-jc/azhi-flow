## The idea in one paragraph

Most agent tools start from an agent and hand it tools. Azhi starts from a **workflow**, and an agent is only
one kind of node in it. Fetching data, parsing, filtering and posting run as ordinary code. A model is called
only where judgment is needed. The whole thing runs durably on Temporal, behind a tool gateway that records
every write, and it tells you **before** the run what is enforced and what is not.

## What you get

<CardGrid stagger>
  <Card title="Durable runs" icon="rocket">
    Crash, restart or timeout and the run resumes. Retries by error class, cancellation, schedules in IANA
    timezones, and waits for offline workers. Built on Temporal.
  </Card>
  <Card title="A plan before anything executes" icon="approve-check">
    `azhi plan` marks every requirement native, bridged, unsupported or unverified, and every policy
    enforced, harness-enforced or unobservable. A run with blockers is refused.
  </Card>
  <Card title="Exactly-once writes" icon="seti:checkbox">
    The tool gateway keeps an action ledger. Kill the process mid-Slack-post and exactly one message exists,
    and `azhi inspect` shows why.
  </Card>
  <Card title="Prompt-injection guard" icon="warning">
    An ungated write after an agent that read untrusted data fails to **compile**. It is caught at authoring
    time, not in production.
  </Card>
  <Card title="Honest cost accounting" icon="information">
    Usage per turn, cost from declared pricing or "unavailable". Never guessed. Per-step budgets and
    daily/monthly spend limits.
  </Card>
  <Card title="Bring your own harness" icon="puzzle">
    Built-in model agent, OpenCode, Claude Agent SDK. Each declares what it can enforce and the plan checks
    it. Anthropic, OpenAI and GitHub Copilot models.
  </Card>
</CardGrid>

## Platform support at a glance

| Platform | Supported as |
|---|---|
| Linux | Server and workers. The reference platform. |
| Windows 10/11 | Everything inside **WSL2**, or the experimental no-Docker local mode natively. |
| macOS | Server in Docker plus a development worker. **Not certified; the install has not been tested on a Mac.** |
